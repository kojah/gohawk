# 100-repository audit (2026-09-25)

Scan-only rescan of the 100 pinned repositories from the cycle audit with every
check enabled and test files excluded (`gohawk -json -enable-all ./...`, the
new default). Binary built from `29cf0c8`, which adds interface holes, the
atomic, spilled-parameter, and global-mutex naming rules, quiet bounded loops,
write-once field paths, and worker pools to the synchronization summaries.
Static analysis only; no candidate code ran. Findings were compared with the
frozen batch labels for the same pins, ignoring frozen findings in `_test.go`
files, which are no longer analyzed.

The analysis driver exits with status 3 when it reports a diagnostic. The scan
script counted that as an incomplete scan; every repository completed.

## New findings

All three are `producerlifecycle/stopped-loop-send`, which did not exist when
the batches were labelled, in grafana/carbon-relay-ng at the pinned revision.

| Position | Verdict | Reason |
| --- | --- | --- |
| `aggregator/aggregator.go:355` | true positive | `Table.Snapshot` loads the configuration without the table lock, while `DelAggregator` shuts the aggregator down before storing the new configuration, so a concurrent snapshot can send on `snapReq` after the run loop returned. |
| `destination/destination.go:216` | true positive | `route.Flush` loads the configuration without the route lock, while `delDestination` shuts the destination down before storing the new configuration, so a concurrent flush can send on `flush` after the relay loop returned. |
| `destination/destination.go:259` | true positive (API hazard) | `WaitOnline` sends to the relay loop and blocks forever after `Shutdown`; only a test calls it. |

No new finding is a false positive. The cycle checks reported nothing, as in
every earlier scan of these repositories.
