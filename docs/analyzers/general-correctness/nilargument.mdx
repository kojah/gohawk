## What it detects

Reports a call that passes a nil pointer, or an aggregate whose field is nil,
to a function summarized as dereferencing that value on every path.

## Why this is flagged

The callee's summary records, as a precondition, the objects it dereferences
on every normal return: a load or store through the pointer, a field
selected beneath it, or a method invoked through an interface it fills, in
its own body or through a callee it hands the value to. The caller's
points-to graph records what each slot certainly holds at the call. When
the two contradict, the call panics on every execution that reaches it,
and the diagnostic names the argument, the field inside it when there is
one, and the callee.

Both halves are must-facts. A callee that checks for nil first, or
dereferences on some path only, requires nothing. A caller whose value is
nil on one branch only, or that replaced it before the call, knows
nothing. Only pointer-typed slots are judged: an interface filled from a
nil pointer is not a nil interface, and the graph does not keep the two
apart, so an interface slot is never a witness.

## How to fix it

Pass a non-nil value, or check for nil in the caller before the call. If the
callee is meant to accept nil, guard the dereference in the callee; its
summary then stops requiring the value.
