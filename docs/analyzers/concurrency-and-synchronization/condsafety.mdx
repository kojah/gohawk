## What it detects

`condsafety/wait-unlocked` is experimental. `Cond.Wait` releases its associated
locker before waiting; an unlocked `sync.Mutex` makes this operation invalid.
The check resolves an exact `sync.NewCond` binding to a fresh local mutex and
uses shared compositional summaries to account for helper acquisitions, releases,
and waits, including cross-package helpers.

The proof requires a complete single-goroutine scope. Borrowed mutexes, opaque
callbacks, custom lockers, RWMutex lockers, changed `Cond.L` fields and concurrent
participants remain unknown. An earlier invalid or blocking operation ends the
proof. Only the first modeled wait is examined: a valid wait might never return.

It does not require Signal or Broadcast to hold the locker, and does not infer
lost wakeups or incorrect predicates from the absence of a loop.

### Accepted code

```go
func lockedWait() {
  var mutex sync.Mutex
  condition := sync.NewCond(&mutex)
  ready := false
  go func() {
    mutex.Lock()
    ready = true
    condition.Signal()
    mutex.Unlock()
  }()
  mutex.Lock()
  for !ready {
    condition.Wait()
  }
  mutex.Unlock()
}
```
