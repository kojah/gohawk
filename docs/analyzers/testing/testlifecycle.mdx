## What it detects

Reports detached test goroutines rooted in a never-cancelled context when they observe cancellation.

### Checks

{/* gohawk:generated-checks:start */}
| Check | Kind | Tier | What it detects |
| --- | --- | --- | --- |
| <CheckIdentity name="context-root" tier="extended" /> | hazard | extended | Reports detached test-owned goroutines rooted in a never-cancelled context. |
{/* gohawk:generated-checks:end */}

## Why this is flagged

A goroutine a test starts but never stops can outlive the test that created it.
Rooted in a context that is never cancelled, it runs on into later tests, where
it can race on shared state, leak resources, or make an unrelated test fail
intermittently. Tying the work to the test's own context, or joining it before
the test returns, keeps each test self-contained.

Further reading: [Package testing: T.Cleanup](https://pkg.go.dev/testing#T.Cleanup).

## How to fix it

Use `t.Context()` or `b.Context()`, or explicitly cancel and join the worker.
