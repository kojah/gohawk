## What it detects

Reports sends reachable after the same channel has been closed.

### Checks

| <CheckIdentity name="send-after-close" tier="core" /> | defect | core | Reports sends reachable after a channel has been closed. |
{/* gohawk:generated-checks:end */}

## Why this is flagged

Sending on a closed channel is a run-time panic, not an error a caller can
recover from in the normal flow, so a reachable send-after-close is a latent
crash. It usually means two parts of the code disagree about which one owns
closing the channel.

Further reading: [The Go Programming Language Specification: Close](https://go.dev/ref/spec#Close).

## How to fix it

Move the close after the final send or separate the channel lifetimes.

### Accepted code

```go
func deferredCloseAfterSends(values []int) <-chan int {
  events := make(chan int)
  go func() {
    defer close(events)
    for _, value := range values {
      events <- value
    }
  }()
  return events
}
```
