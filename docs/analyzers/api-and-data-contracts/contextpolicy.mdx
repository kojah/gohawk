## What it detects

Reports misplaced `context.Context` parameters, contexts stored in structs, and definitely nil context arguments.

### Checks

{/* gohawk:generated-checks:start */}
| Check | What it detects |
| --- | --- |
| <CheckIdentity name="context-first" /> | Reports misplaced context.Context parameters while allowing additional contexts after a leading context and one context after a testing handle. |
| <CheckIdentity name="context-storage" /> | Reports context.Context values stored in structs. |
| <CheckIdentity name="nil-context" /> | Reports definitely nil context.Context arguments. |
{/* gohawk:generated-checks:end */}

## Why this is flagged

Context placement and lifetime are API contracts. Consistent leading parameters make cancellation easy to propagate, while stored or nil contexts obscure ownership.

## How to fix it

Accept a real context in the conventional leading position and pass it directly to the work that needs it.
